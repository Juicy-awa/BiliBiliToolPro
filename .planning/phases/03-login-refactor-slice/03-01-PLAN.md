## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External → LoginDomainService | User-provided cookies and QR code scan input cross from external to internal via ILoginDomainService |
| LoginTaskAppService → Persistence | Cookie persistence to QingLong env or JSON file crosses trust boundary to storage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | LoginTaskAppService.SaveCookieAsync | accept | Cookie validation happens in ILoginDomainService.SetCookieAsync (domain layer, out of Phase 3 scope). Phase 3 only refactors orchestration, not validation logic. |
| T-03-02 | Information Disclosure | Cookie persistence paths | accept | Platform configuration (QingLong vs JSON) determines persistence location. This is operational config, not a Phase 3 refactor concern. ASVS L1 does not require encryption at rest for this brownfield scenario. |
| T-03-03 | Denial of Service | QR code login flow | accept | Rate limiting and timeout handling exist in domain service layer (ILoginDomainService.LoginByQrCodeAsync). Phase 3 preserves existing behavior; no new DoS vectors introduced. |

</threat_model>

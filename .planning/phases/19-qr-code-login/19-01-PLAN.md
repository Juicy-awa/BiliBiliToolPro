   - Calls `passportApi.GenerateQrCode()` (reuses existing API, per D-01)
   - On success, generates a PNG byte array using QRCoder's `PngByteQRCode`:
     ```csharp
     var qrGenerator = new QRCodeGenerator();
     var qrCodeData = qrGenerator.CreateQrCode(url, QRCodeGenerator.ECCLevel.L);
     var pngQrCode = new PngByteQRCode(qrCodeData);
     var pngBytes = pngQrCode.GetGraphic(20);
     var base64 = Convert.ToBase64String(pngBytes);
     ```
   - Returns `QrLoginGenerateResult { QrImageBase64, QrcodeKey, OnlineUrl }`
   - Does NOT render to console/logger (per D-01: "does NOT render to console/logger")
   - Also returns `OnlineUrl` for potential fallback link (agent's discretion — include the "高清二维码" URL like Console flow)

2. **`Task<QrLoginCheckResult> CheckQrLoginAsync(string qrcodeKey, CancellationToken ct)`** on `ILoginDomainService`:
   - Calls `passportApi.CheckQrCodeHasScaned(qrcodeKey)` (reuses existing API, per D-01)
   - Parses the `HttpResponseMessage`:
     - If not `IsSuccessStatusCode`: returns `QrLoginCheckResult { Status = Error, Message = "检测接口异常" }`
     - Deserializes content as `BiliApiResponse<TokenDto>`
     - If `content.Data.Code == 86038`: returns `QrLoginCheckResult { Status = Expired, Message = content.Data.Message }` (per D-04)
     - If `content.Data.Code == 0`: extracts `Set-Cookie` headers via `CookieInfo.ConvertSetCkHeadersToCkStr()`, creates `BiliCookie` via `CookieStrFactory<BiliCookie>.CreateNew()`, calls `Check()`, returns `QrLoginCheckResult { Status = Success, Cookie = biliCookie }`
     - Otherwise: returns `QrLoginCheckResult { Status = Waiting, Message = content.Data.Message }`

   - `src/Ray.BiliBiliTool.DomainService/Dtos/QrLoginCheckResult.cs`: `{ QrLoginStatus Status, string? Message, BiliCookie? Cookie }` with enum `QrLoginStatus { Waiting, Success, Expired, Error }`

1. **Create `QrLoginDialog.razor`** — a MudDialog component with a state machine (per D-03, D-04, D-06):

   **State machine:** `Initial → Generating → Scanning → Success | Failed | Expired`

   **Component structure:**
   ```razor
   @using MudBlazor
   @using Ray.BiliBiliTool.DomainService.Dtos
   @using Ray.BiliBiliTool.Web.Services.Pages.BiliAccount
   @inject IBiliAccountPageWorkflow Workflow

   <MudDialog>
       <DialogContent>
           @switch (_state)
           {
               case QrLoginState.Generating:
                   <MudProgressCircular Indeterminate="true" />
                   <MudText>正在生成二维码...</MudText>
                   break;

               case QrLoginState.Scanning:
                   <MudText Typo="Typo.body2">请使用Bilibili App扫描二维码</MudText>
                   <img src="data:image/png;base64,@_qrImageBase64" style="width:200px;height:200px;" />
                   <MudText Typo="Typo.caption">@($"等待扫描... {_pollCount}/10")</MudText>
                   <MudProgressLinear Value="@(_pollCount * 10)" Color="Color.Primary" />
                   break;

               case QrLoginState.Success:
                   <MudText Color="Color.Success">登录成功！正在保存...</MudText>
                   break;

               case QrLoginState.Failed:
               case QrLoginState.Expired:
                   <MudText Color="Color.Error">@_errorMessage</MudText>
                   break;
           }
       </DialogContent>
       <DialogActions>
           @if (_state == QrLoginState.Failed || _state == QrLoginState.Expired)
           {
               <MudButton Color="Color.Primary" Variant="Variant.Filled" OnClick="Retry">重试</MudButton>
           }
           <MudButton OnClick="Cancel">取消</MudButton>
       </DialogActions>
   </MudDialog>
   ```

   **Code section:**
   - Inject `IBiliAccountPageWorkflow Workflow`
   - `[CascadingParameter] IMudDialogInstance MudDialog`
   - `QrLoginState` enum defined in `@code` block: `Generating, Scanning, Success, Failed, Expired`
   - Fields: `_state`, `_qrImageBase64`, `_qrcodeKey`, `_pollCount`, `_errorMessage`, `_pollingCts`
   - `OnInitializedAsync()` → calls `StartQrLoginAsync()`
   - `StartQrLoginAsync()`:
     1. Set state to `Generating`
     2. Call `Workflow.QrLoginGenerateAsync()` → get QR image + qrcode_key
     3. Set `_qrImageBase64`, `_qrcodeKey`, set state to `Scanning`
     4. Enter poll loop (max 10 iterations, 5-second delay per iteration, per D-03):
        - Increment `_pollCount`, call `StateHasChanged()` to update UI
        - Call `Workflow.QrLoginPollAsync(_qrcodeKey)`
        - If `result.Status == Success`: set state to `Success`, call `Workflow.QrLoginCompleteAsync(result.Cookie)`, close dialog with success
        - If `result.Status == Expired` (code 86038, per D-04): set state to `Expired`, set `_errorMessage = "二维码已过期"`, break
        - If `result.Status == Error`: set state to `Failed`, set `_errorMessage = result.Message`, break
        - `await Task.Delay(5000)` (per D-03: poll interval 5 seconds)
     5. If loop ends without success: set state to `Failed`, set `_errorMessage = "登录超时，请重试"` (per D-04)
   - `Retry()` (per D-04): reset `_pollCount = 0`, `_errorMessage = null`, call `StartQrLoginAsync()` again — dialog stays open
   - `Cancel()`: cancel any pending CTS, `MudDialog.Cancel()`
   - Use `CancellationTokenSource` (`_pollingCts`) for clean cancellation on dialog close or retry

   **Blazor Server considerations:**
   - `StateHasChanged()` after each poll count update ensures the UI refreshes (Blazor Server with SignalR handles this naturally)
   - Use `await InvokeAsync(StateHasChanged)` if cross-thread issues arise
   - The dialog runs on the server — no JS interop needed for polling

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser ↔ Blazor Server (SignalR) | QR image and poll state communicated over SignalR connection |
| Blazor Server ↔ Bilibili Passport API | QR generation and scan-check calls to external Bilibili API |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01 | Spoofing | QR code URL | mitigate | QR URL comes from `IPassportApi.GenerateQrCode()` directly (server-side call to Bilibili API) — no user input involved in URL construction. Server validates API response code == 0 before returning QR data. |
| T-19-02 | Tampering | Poll loop | accept | Poll uses server-side `qrcode_key` generated by Bilibili. Key is not exposed to user manipulation (stored in component field, transmitted over SignalR). Low attack surface. |
| T-19-03 | Information Disclosure | Cookie display | mitigate | Dialog only shows QR image, never displays raw cookie string. Cookie is persisted directly to SQLite via workflow seam — no intermediate display in UI. |
| T-19-04 | Denial of Service | Poll loop exhaustion | mitigate | Poll loop bounded to 10 attempts at 5-second intervals (50s max). CancellationTokenSource ensures cleanup on dialog close. Single QR session per dialog instance. |
| T-19-05 | Elevation of Privilege | Cookie save | accept | Page has `[Authorize]` attribute — only authenticated admin users can access BiliAccount page and trigger QR login. Cookie saved to same SQLite table as manual add. |
</threat_model>

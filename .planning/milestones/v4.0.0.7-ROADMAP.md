# Milestone v4.0.0.7: Bili Account Management

**Status:** ✅ SHIPPED 2026-05-07
**Phases:** 17–19
**Total Plans:** 4

## Overview

Added a Web-based "Bili Account" page for viewing, adding, editing, deleting, and reordering Bili accounts (cookies), backed by SQLite as the primary configuration source for Web. QR code login lets maintainers add accounts without manually copying cookie strings. `cookies.json` retained as a lower-priority fallback so existing Console-host users are not broken.

### Phase 18: Account CRUD Operations

**Goal**: Enable adding, editing, deleting, and reordering Bili accounts through the Web UI.
**Requirements:** ACCT-03, ACCT-04, ACCT-05, ACCT-06
**Plans**: 2 plans

Plans:
- [x] 18-01-PLAN.md — Account add/edit/delete with config reload (ACCT-03, ACCT-04, ACCT-05)
- [x] 18-02-PLAN.md — Account reorder with atomic key swap (ACCT-06)

**Details:**
1. AddAsync: Reads current BiliBiliCookies count, writes next index to SQLite
2. UpdateAsync: Sets BiliBiliCookies__{index} with new cookie string (INSERT OR REPLACE)
3. DeleteAsync: Re-keys all higher indices down by 1 via BatchSet, then deletes the old last key
4. ReorderAsync: Reads current list, swaps two BiliBiliCookies__N keys atomically via BatchSet
5. MudDialog components for Add, Edit, Delete with confirmation
6. Up/down arrow buttons for reorder with boundary guards

**Commits:** `750c292`, `6784f5e`, `007a8de`, `a11b5e2`, `5a25823`, `2eca048`

### Phase 19: QR Code Login

**Goal**: Enable QR code login directly in the Web browser so maintainers can add accounts without manually copying cookie strings.
**Requirements:** ACCT-02
**Plans**: 1 plan

Plans:
- [x] 19-01-PLAN.md — QR code login in Web browser

**Details:**
1. GenerateQrCodeWebAsync: calls passportApi.GenerateQrCode(), generates PNG via PngByteQRCode, returns base64 + qrcode_key + online URL
2. CheckQrLoginAsync: calls passportApi.CheckQrCodeHasScaned(), parses response, returns Waiting/Success/Expired/Error
3. QrLoginDialog.razor: MudDialog with state machine (Generating → Scanning → Success/Failed/Expired), polling progress, retry, online URL fallback
4. Cookie enrichment via SetCookieAsync before saving to SQLite
5. Poll loop: 5s interval, 10 max attempts

**Commits:** `1e7d5bc`, `25d97b5`, `bff8ee2`, `10cdd5f`

## Milestone Summary

**Key Decisions:**
- Decision: Keep cookies.json as fallback source (not remove it) — Rationale: Existing Console-host users who haven't migrated to SQLite would break
- Decision: QR login domain service generates base64 PNG (not terminal output) — Rationale: Web browser can display PNG via img tag, terminal QR rendering doesn't apply
- Decision: Cookie enrichment via SetCookieAsync before saving — Rationale: Raw QR login cookie needs expiry enrichment before storage

**Issues Resolved:**
- IConfigurationRoot DI injection error (Phase 18) — resolved by injecting IConfiguration and casting to IConfigurationRoot
- Test double compilation failures (Phase 19) — resolved by adding stub implementations for new interface methods

**Issues Deferred:**
- Pre-existing characterization test failure: `Login_flow_preserves_current_step_order_and_emits_diagnostics` (from Phase 5)
- ARCH-04: Notification adapter/port boundary (from Phase 6)
- Nyquist compliance not performed for milestone phases (gsd-sdk unavailable)

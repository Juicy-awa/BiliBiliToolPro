# Milestone v4.0.0.1: Brownfield Refactor

**Status:** ✅ SHIPPED 2026-05-03
**Phases:** 1–6
**Total Plans:** 13

## Overview

Brownfield refactor of BiliBiliToolPro establishing explicit dependency direction, module-level registration seams, characterization and host integration test coverage for critical Login/DailyTask flows, thin Quartz scheduling shells, and a typed exception/adapter boundary model for HTTP, EF, and domain-service integrations.

The goal was not to replace the product but to make the current system safer to change by clarifying layer boundaries, reducing coupling, and adding test coverage around critical execution paths.

### Phase 6: Integration Boundary And Failure Model
**Goal**: External integrations and failures sit behind consistent adapters with diagnosable outcomes for critical flows.
**Depends on**: Phase 5
**Requirements**: ARCH-04, FLOW-04, QUAL-01
**Plans**: 4 plans

Plans:
- [x] 06-01-PLAN.md — Create BiliException hierarchy in Domain + extract BiliResiliencePolicies with split policies and 30s timeout.
- [x] 06-02-PLAN.md — Introduce IExecutionLogRepository and IUserRepository; remove direct EF factory injection from LogsDialog and AuthService.
- [x] 06-03-PLAN.md — Replace all generic Exception throws in seven DomainService files with typed BiliBusinessException/BiliIntegrationException.

**Success Criteria Achieved:**

2. ✅ Maintainers can distinguish expected business failures (BiliBusinessException), integration failures (BiliIntegrationException), and validation failures (BiliValidationException).
3. ✅ EF dependencies reachable through IExecutionLogRepository and IUserRepository adapter boundaries.
4. ✅ Outbound API policies explicit: MutatingPolicy for side-effecting clients, ReadOnlyPolicy for idempotent clients, 30s timeout across all.

**Key Deliverables:**
- `BiliException` → `BiliBusinessException` / `BiliIntegrationException` / `BiliValidationException` hierarchy in `Domain.Exceptions`

- 8 new unit tests in BiliAgentTest covering typed exception paths and resilience constants

**Deferred (D-05):** `throw new Exception("Current password is incorrect.")` in `AuthService.cs` — intentionally excluded from sweep.
**Partial (ARCH-04):** Notification-facing boundary not established — notifications still flow through `Ray.Serilog.Sinks.Batched` directly without an explicit adapter port.

## Milestone Summary

**Timeline:** 2026-04-20 (project start) → 2026-05-03 (shipped)
**Total execution time:** ~1.7 hours active execution across all phases

**Key Decisions:**
- Brownfield strategy: preserve all existing behavior while restructuring (no big-bang rewrite)
- ArchUnitNET for executable dependency direction enforcement (Phase 1)
- Separate dedicated test projects for characterization and host integration (Phase 2)
- Logger-based diagnostic markers rather than tracing framework (Phase 2)
- XML documentation pattern for application service orchestration layers (Phase 3)
- Expression-body DoExecuteAsync as the thin-shell pattern for all Quartz jobs (Phase 5)
- BiliException abstract hierarchy in Domain layer; DomainService and Agent reference Domain (Phase 6)
- Split ReadOnly/Mutating resilience policies by idempotency (Phase 6, D-08/D-09/D-10)
- `AuthService` generic throw excluded from sweep — not a Bilibili API error boundary (Phase 6, D-05)

**Issues Resolved:**
- Application-to-Agent DTO leakage captured in explicit allowlist (Phase 1)
- ArchUnitNET API usage corrected from unsupported overloads (Phase 1)
- Quartz SQLite delegate import restored after scheduler setup move (Phase 1)
- Pre-existing format string bugs in BiliCookie (`{1}` → `{0}`, named → positional) fixed as part of Phase 6 sweep

**Issues Deferred:**
- `AuthService` generic `Exception` throw (D-05) — excluded from exception sweep
- Application-to-Agent DTO allowlist cleanup — deferred to future milestone
- Notification adapter/port boundary — ARCH-04 partial gap, deferred to future milestone
- `Daily_task_multi_account_wrapper_continues_after_account_failure` test — pre-existing failure, root cause uninvestigated

**Technical Debt Incurred:**

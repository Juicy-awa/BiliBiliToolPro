# Requirements Archive: v4.0.0.7 Bili Account Management

**Archived:** 2026-05-07
**Status:** ✅ All requirements satisfied (7/7)

## Requirements

### Account CRUD

- [x] **ACCT-01**: Maintainer can view a list of all Bili accounts showing UserId and full cookie string in the Web UI
  - **Outcome:** ✅ Satisfied — Phase 17. MudTable with UserId + cookie columns, truncation with tooltip, loading spinner, empty state.

- [x] **ACCT-02**: Maintainer can add a new Bili account by scanning a QR code displayed in the Web browser
  - **Outcome:** ✅ Satisfied — Phase 19. QrLoginDialog MudDialog with state machine (Generating → Scanning → Success/Failed/Expired), base64 PNG via QRCoder, polling (5s × 10 attempts), retry, online URL fallback. Cookie enrichment via SetCookieAsync.

- [x] **ACCT-03**: Maintainer can add a new Bili account by pasting a raw cookie string into a text field
  - **Outcome:** ✅ Satisfied — Phase 18. AddAccountDialog MudDialog with textarea, writes to next SQLite index.

- [x] **ACCT-04**: Maintainer can edit an existing account's cookie string
  - **Outcome:** ✅ Satisfied — Phase 18. EditAccountDialog MudDialog pre-filled with current cookie, updates via INSERT OR REPLACE.

- [x] **ACCT-05**: Maintainer can delete an existing account
  - **Outcome:** ✅ Satisfied — Phase 18. DeleteAccountDialog confirmation dialog, re-keys higher indices down by 1.

- [x] **ACCT-06**: Maintainer can reorder accounts to change execution order
  - **Outcome:** ✅ Satisfied — Phase 18. Up/down arrow buttons, atomic key swap via BatchSet, boundary guards (disabled on first/last).

### Storage

- [x] **ACCT-07**: Keep `config/cookies.json` as a fallback configuration source in Web host (loaded before `AddSqlite`); SQLite `bili_appsettings` table remains the highest-priority config source for Bili cookies
  - **Outcome:** ✅ Satisfied — Phase 17. `cookies.json` loaded via AddJsonFile before AddSqlite in Program.cs. SQLite wins for overlapping keys.
